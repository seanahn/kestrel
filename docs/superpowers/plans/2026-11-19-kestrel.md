# kestrel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use trivialpowers:subagent-driven-development (recommended) or trivialpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VS Code extension that lists the user's open GitHub PRs in a bottom-panel tab, shows each one's state (merge / failed CI / blockers / …), hands a prompt to the agent on click, and merges on confirm; plus a `perch.insertText` command in perch.

**Architecture:** Pure modules (review-summary parsing, PR → row state, the row tracker, interval choice, merge-method choice) carry the logic and the tests. Thin host modules wrap `gh` (accounts/tokens), GitHub GraphQL (Node `https`), the poller, the webview view and the hand-off. `extension.js` wires them. Same layout and tooling as `/git/chirp`.

**Tech Stack:** Plain JavaScript (CommonJS), VS Code API `^1.90.0`, Node `https`, `node --test`, jsdom (dev only).

**Spec:** `docs/notes/101-design.md`

The design holds every design decision; this plan holds build steps and
code-level names only, and is deleted when the work merges. If a decision
changes during the build, change the design in the same commit.

## Global Constraints

- No runtime dependencies; `devDependencies` only `jsdom`. No build step.
- `engines.vscode: "^1.90.0"`, `publisher: "seanahn"`, `license: "MIT"`, repo `https://github.com/seanahn/kestrel`, version `0.1.0`.
- Public repo: no file, fixture, test, doc or commit message names the user's employer, its GitHub org, its repos or the user's work account. Fixtures use `acme/widgets`, `acme/api`, `octo-dev/tools`, accounts `octo-dev` and `octo-work`. Task 1 adds a test that enforces this from a gitignored word list.
- Tests never touch the network or the real `gh`. Every `gh` call goes through one injected `run(args)`; every HTTP call through one injected `request(token, body)`.
- Only github.com (`https://api.github.com/graphql`).
- Never sends a prompt to an agent; never merges without the modal confirm.
- No `console.log` in shipped code; diagnostics go to an output channel named `kestrel`.
- Code style follows chirp: `'use strict'`, short header comment per file citing the design section, `node --check` clean.

## Review Focus

1. **A repo with no CI at all**: rollup is `null` and there are zero checks. The row must reach **merge** when `CLEAN`, not sit at "checks 0/0". (Task 3 test `no checks at all is mergeable`.)
2. **More than 50 open PRs**: a truncated search would make the overflow look merged and drop rows. Search must paginate. (Task 5 test `paginates search`.)
3. **Reload of VS Code**: the first poll after activation must not highlight every row or raise the badge as "new events". (Task 6 test `first apply is quiet`.)
4. **A PR title with HTML** (`<img onerror>` / `&`): must render as text. (Task 9 test `titles are text`.)
5. **Legacy commit statuses** (`StatusContext` with `ERROR`/`FAILURE`/`PENDING`) next to check runs: must count as failure/pending like check runs. (Task 5 test `normalizes status contexts`.)

### Task 3: Row state (the design's state table)

**Files:** Create `src/model.js`, `test/model.test.js`

**Interfaces:**
- Consumes: `summaryForHead` (Task 2).
- Produces the normalized PR shape every later task uses:
  ```
  Pr = { id, url, number, title, repo /* 'owner/name' */, account, isDraft, updatedAt,
         headOid, mergeable /* 'MERGEABLE'|'CONFLICTING'|'UNKNOWN' */, mergeState /* GitHub mergeStateStatus */,
         reviewDecision /* string|null */, checks: Array<{ name, state: 'pending'|'success'|'failure' }>,
         reviews: Array<{ body, commitOid, submittedAt }>, unresolvedThreads: number,
         mergeMethods: { squash: boolean, merge: boolean, rebase: boolean } }
  ```
  `rowState(pr: Pr): RowState` where
  ```
  RowState = { rule: 1..9, key: string, text: string, dot: 'red'|'green'|'running'|'dim',
               actionable: boolean, action: { kind: 'prompt', prompt: string } | { kind: 'merge' } | { kind: 'open' } | null,
               extra: { text: string, prompt: string } | null }
  ```
  and `ACTIONABLE_RULES = [2, 3, 4, 5, 7, 9]`.

Rules, in order (the design's table): 1 `isDraft`; 2 `mergeable === 'CONFLICTING'`; 3 any check `failure`; 4 summary on head with `blockers > 0`; 5 `reviewDecision === 'CHANGES_REQUESTED'`; 6 any check `pending`, or `mergeable === 'UNKNOWN'`, or `mergeState === 'UNKNOWN'`; 7 `mergeState === 'BEHIND'`; 8 `mergeState === 'BLOCKED'` or any other non-mergeable state; 9 `mergeState` in `CLEAN`, `UNSTABLE`, `HAS_HOOKS`.

Exact texts and prompts (`{ref}` = `repo#number`, `{url}` = `url`):

| rule | text | dot | action |
|---|---|---|---|
| 1 | `draft` | dim | prompt `PR {ref} is a draft; check whether it is ready to mark ready for review ({url})` |
| 2 | `conflicts` | red | prompt `resolve the merge conflicts on PR {ref} ({url})` |
| 3 | `CI failed: {first}` + ` and {n} more` when n>0 | red | prompt `check the failing \`{first}\` check on PR {ref} ({url})` |
| 4 | `1 blocker` / `{n} blockers` | red | prompt `check the blocker comments on PR {ref} ({url})` |
| 5 | `changes requested` | red | prompt `check the requested changes on PR {ref} ({url})` |
| 6 | `checks {done}/{total}`, or `waiting for GitHub` when total is 0 | running | `null` |
| 7 | `behind base` | red | prompt `update PR {ref} with its base branch ({url})` |
| 8 | `blocked: needs review` when `reviewDecision === 'REVIEW_REQUIRED'`, else `blocked` | dim | `{ kind: 'open' }` |
| 9 | `merge` | green | `{ kind: 'merge' }` |

`key` is `rule` plus the reason: the first failed check's name for 3, the blocker count for 4, nothing for the rest. Progress such as `done` is not part of `key`.

`extra` is `null` for rules 1, 4 and 6. Otherwise:
- if the summary on head has `findings > 0`: `{n} finding(s)`, prompt `check the findings on PR {ref} ({url})`;
- else if there's no summary on head and `unresolvedThreads > 0`: `{n} unresolved comment(s)`, prompt `check the unresolved review comments on PR {ref} ({url})`;
- else `null`.

- [ ] **Step 1: Write a table-driven test**, `test('state table')`, with a `pr(overrides)` fixture builder (repo `acme/widgets`, number 42, url `https://github.com/acme/widgets/pull/42`, CLEAN, MERGEABLE, all checks success, no reviews). Include one case per row above asserting `rule`, `text`, `dot`, `action`. Also these named tests:
  - `failure beats running`: checks `[failure 'test', pending 'lint']` → rule 3.
  - `conflict beats failure` → rule 2.
  - `stale summary ignored`: a blocker summary on an old commit with all checks green and CLEAN → rule 9, `extra` null.
  - `no checks at all is mergeable`: `checks: []`, CLEAN → rule 9.
  - `progress is not part of the key`: `checks 3/5` and `checks 4/5` share a `key`.
  - `findings ride on merge` → rule 9 with `extra.text === '3 findings'`.
  - `unresolved fallback`: no summary, `unresolvedThreads: 1` → `extra.text === '1 unresolved comment'`.
  - `actionable` is true exactly for `ACTIONABLE_RULES`.
- [ ] **Step 2: Run.** Expected: FAIL.
- [ ] **Step 3: Implement `rowState`.**
- [ ] **Step 4: Run.** Expected: PASS.
- [ ] **Step 5: Commit** `feat: PR row state`.

### Task 5: GitHub GraphQL client

**Files:** Create `src/github.js`, `test/github.test.js`, `test/fixtures/` (JSON responses, made-up names only)

**Interfaces:**

  - `listPrs(token): Promise<{ items: ListItem[], rateLimit: { remaining: number, resetAt: string, cost: number } }>` with `ListItem = { id, url, updatedAt, headOid, mergeable, mergeState, isDraft, reviewDecision, rollup /* 'SUCCESS'|'FAILURE'|'PENDING'|'EXPECTED'|'ERROR'|null */ }`

  - `prByUrl(token, url): Promise<Pr|null>`, using `resource(url:)`
  - `merge(token, { id, method: 'SQUASH'|'MERGE'|'REBASE', expectedHeadOid }): Promise<void>`
  - `class GitHubError extends Error { kind: 'auth'|'throttle'|'partial'|'refused'|'offline'|'http'; status?: number; retryAfterMs?: number }`
  - `normalizeChecks(contexts: object[]): Pr['checks']`

Mapping: a `CheckRun` with `status !== 'COMPLETED'` is pending; with conclusion `FAILURE|TIMED_OUT|CANCELLED|ACTION_REQUIRED|STARTUP_FAILURE` it is failure; anything else is success. A `StatusContext` in `PENDING|EXPECTED` is pending, in `FAILURE|ERROR` is failure, in `SUCCESS` is success. `unresolvedThreads` counts `reviewThreads(first: 50)` nodes with `isResolved === false`. `mergeMethods` comes from `repository { squashMergeAllowed mergeCommitAllowed rebaseMergeAllowed }`. Search query string: `is:pr is:open author:@me archived:false`, 50 per page, following `pageInfo.endCursor` up to 4 pages (200 PRs).

Errors: HTTP 401 → `auth`. 429, or 403 with `retry-after` or a body message containing `secondary rate limit` → `throttle`, with `retryAfterMs` from `retry-after` seconds when given. A network error (`ECONNRESET`, `ENOTFOUND`, `ETIMEDOUT`, …) → `offline`. A 200 with an `errors` array → `partial` (message = first error's `message`) for queries, `refused` for `merge`. Other non-2xx → `http`.

### Task 6: Tracker (rows, events, badge, notes)

**Files:** Create `src/tracker.js`, `test/tracker.test.js`

**Interfaces:**
- Consumes: `rowState` and `Pr` (Task 3).
- Produces: `createTracker({ now: () => number })` →
  - `apply(account: string, prs: Pr[]): void`. This is a complete, successful result for that account: it replaces that account's rows, adds new ones and removes missing ones.
  - `fail(account: string, note: string): void`. Keeps that account's rows and sets its note.
  - `drop(account: string, note: string): void`. Removes that account's rows and sets its note.
  - `clearNote(account)`, `setGlobalNote(text|null)`, `remove(url)`, `markSeen(url)`, `setError(url, text|null)` (a merge refusal shown on the row until its next `apply`)
  - `rows(): Row[]`, where `Row = { pr: Pr, state: RowState, changedAt: number, highlight: boolean, error: string|null }`, sorted by `changedAt` descending
  - `badge(): number` (count of `state.actionable`), `notes(): string[]` (global note first), `anyRunning(): boolean` (any rule 6), `onChange(fn): void`

Rules:
- A row's first appearance in the first `apply` for an account sets `changedAt = Date.parse(pr.updatedAt)` with no highlight. A PR that first appears in a later `apply` gets `changedAt = now()`, and highlight if actionable.
- On `apply`, a row whose `state.key` changed gets `changedAt = now()`, and `highlight = state.actionable`. Same key → `changedAt` and `highlight` unchanged; `state` (text) updated.
- Rows are keyed by `pr.url`. `apply` for account A never touches rows owned by B.

### Task 7: Poller and sync round

**Files:** Create `src/poller.js` (adapted from `/git/chirp/src/poller.js`), `src/sync.js`, `test/poller.test.js`, `test/sync.test.js`

**Interfaces:**
- Consumes: `createAccounts` (Task 4), `createClient`/`GitHubError` (Task 5), `createTracker` (Task 6).
- Produces:
  - `pickInterval({ focused: boolean, anyRunning: boolean, fastUntil: number, now: number }): number`. 10000 if `now < fastUntil`, else 20000 if `anyRunning`, else 60000; times 4 when not focused (including the fast interval).
  - `createPoller({ run, interval: () => number, timers?, onNote: (text|null) => void })` → `{ start, stop, kick }`. Never runs twice at once. `GitHubError` `throttle`: wait `retryAfterMs`, else back off 5 s doubling to 5 min, note `GitHub is throttling, retrying`. `offline`: the same backoff, note `Offline, retrying`. An error with `kind: 'rate'` and `retryAfterMs`: wait that long, note = its message. Success clears the note.
  - `createSync({ accounts, client, tracker, now })` → `{ run(): Promise<void>, watch(url: string): void, fast(): void, fastUntil(): number, tokenFor(login): Promise<string> }`. `watch` and `fast` set `fastUntil = now() + 300000`.

`sync.run()` per account, in order:
1. Get the token.
2. `listPrs`. Pick ids needing detail: new, or a changed `updatedAt|headOid|mergeable|mergeState|isDraft|reviewDecision|rollup`, or rollup `PENDING|EXPECTED|null`-with-no-cached-detail. Cache details per id otherwise.
3. `detailPrs` those.
4. `tracker.apply(login, prs)` with `account` set.

Also:
- On `auth`: refetch the token with `{ fresh: true }` and retry once. A second `auth`, or a token failure, means `tracker.drop(login, '<login>: gh login expired, run \`gh auth login\`')`.
- On `partial`: `tracker.fail(login, '<login>: <message>')`.
- `throttle`/`offline`: rethrow to the poller.
- Watched URLs not in any account's list are fetched with `prByUrl` (using the first account's token) and included in that account's `apply`. Once a list returns them, they're unwatched.
- After the round, if the lowest `rateLimit.remaining` is under 200, throw `{ kind: 'rate', retryAfterMs: resetAt - now, message: 'GitHub rate limit, resuming at HH:MM' }` (local time).
- `NoGhError` from `accounts.list()` → `tracker.setGlobalNote(err.message)`, and the poller retries in 30 s (throw `{ kind: 'rate', retryAfterMs: 30000, message: err.message }`).

- [ ] **Step 1: Poller tests**, ported from chirp's `test/poller.test.js` and reshaped for `interval()`, `rate` and the new note texts. `pickInterval` table test: 10000/20000/60000 and ×4.
- [ ] **Step 2: Sync tests** with fake accounts/client: `only changed PRs get detail` (second round with one changed `updatedAt` → `detailPrs` called with exactly that id); `pending rollup always refreshed`; `401 then fresh token succeeds`; `401 twice drops account`; `partial keeps rows`; `rate floor throws rate wait` (remaining 150, assert `retryAfterMs` and message format); `watched url included until listed`; `no gh sets note`.

### Task 8: Hand-off and merge

**Files:** Create `src/handoff.js`, `src/merge.js`, `test/handoff.test.js`, `test/merge.test.js`

**Interfaces:**
- Consumes: the vscode stub (Task 1), `GitHubError` (Task 5), the tracker (Task 6), `sync.tokenFor` (Task 7).
- Produces:
  - `createHandoff(vscode)` → `{ send(prompt: string): Promise<'perch'|'clipboard'> }`. It caches whether `perch.insertText` is in `getCommands(true)`, and re-checks on `vscode.extensions.onDidChange`. If present, `executeCommand('perch.insertText', prompt)`; a result `=== true` means `'perch'`. Otherwise, or on a throw, it copies to the clipboard and calls `setStatusBarMessage('Prompt copied. Paste it into your agent.', 4000)`.
  - `pickMethod(allowed: Pr['mergeMethods'], preferred: 'squash'|'merge'|'rebase'): 'SQUASH'|'MERGE'|'REBASE'|null` (preferred if allowed, else the first allowed of squash, merge, rebase).
  - `METHOD_LABEL = { SQUASH: 'Squash and merge', MERGE: 'Create a merge commit', REBASE: 'Rebase and merge' }`.
  - `createMerger({ vscode, client, tokenFor, tracker, pollNow, preferred: () => string })` → `{ merge(url): Promise<'merged'|'cancelled'|'refused'|'unconfirmed'|'busy'|'gone'>, busy(url): boolean }`.

`merge(url)`:
1. Already in flight → `'busy'`. Row missing → `'gone'`.
2. `showWarningMessage('Merge {ref} "{title}"?', { modal: true }, METHOD_LABEL[m])`. Anything but that label → `'cancelled'`.
3. Mark busy (the row link shows `merging…`).
4. `client.merge(token of row.pr.account, { id, method, expectedHeadOid: row.pr.headOid })`.
5. Success → `tracker.remove(url)`, `'merged'`. `refused` → `tracker.setError(url, message)`, `'refused'`. Any other error → `tracker.setError(url, 'Merge not confirmed: ' + message)`, then `pollNow()`, `'unconfirmed'`. Never retry.
6. Clear busy in `finally`.

If `pickMethod` returns `null`: `setError(url, 'This repo allows no merge method kestrel can use')`, `'refused'`.
